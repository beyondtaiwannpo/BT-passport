# BT Passport — 活動格子翻面 設計規格

2026-08-25。這份文件補充 `2026-08-16-bt-passport-design.md` 與
`2026-08-22-guide-page-and-slot-order-design.md`，不取代它們。

這一輪只做翻面。**不改任何文案、不動資料庫、不碰 `activities` 的內容。**

---

## 1. 為什麼

一格現在要塞五樣東西：分類標籤、標題、說明、章、心得、照片。
蓋完章之後說明還占著位置，但那時候已經不需要它了 —— 它是給還沒做的人看的。

護照本來就是一頁一頁翻的，格子會翻面符合這個隱喻。

- **正面（未蓋章）**：分類標籤、標題、英文標題、說明、蓋章入口
- **正面（已蓋章）**：分類標籤、標題、**章**、翻面按鈕
- **背面（已蓋章）**：說明、心得、照片、翻回正面的按鈕

未蓋章只顯示正面。**已蓋章也預設顯示正面** —— 章在那裡。兩面都要能手動翻到另一面。

### 1.1 章為什麼在正面（2026-08-25 修訂）

初版把章放在背面、蓋章後預設翻到背面。**上線後發現問題**：翻到正面只有題目和說明，
跟沒蓋過長得一模一樣，要一格一格翻到背面才知道自己蓋了什麼。

使用者的裁定：**章是這本護照的主角，永遠該在正面。說明是「還沒蓋章時才需要」的東西，
蓋完就該退到背面。**

**日期不另外放在背面。** 它已經在章上（`stampHTML` 的第三行）——背面再放一次
就是同一個資訊的兩個來源。

已蓋章的正面也不放英文標題：章上的 `s2` 就是 `title_en`，重複。

## 2. §3.4 的例外 —— 這是新的視覺元件

原規格 §3.4 寫「新增的畫面不引入任何新的視覺元件，一律沿用原型既有的
`.card` / `.btn` / `label` / `.wnote` 樣式」。

**翻面卡是新的視覺元件，這是明確授權的例外。** 使用者 2026-08-25 直接指名：

> 這是新的視覺元件，規格 §3.4 說不引入新元件 —— 這是明確的例外，
> 請在規格檔記錄這個裁定與理由。

理由（使用者的原話）：一格要塞五樣東西；蓋完章之後說明變成死重量；
護照本來就是一頁一頁翻的。

**這個例外只涵蓋翻面卡本身。** 它不是「以後可以自由新增元件」的先例 ——
三色、兩字體、不加漸層、不加陰影、不加第四色，全部照舊。

## 3. 結構

`.slot` 從 `<button>` 變成 `<div>`。**這不是風格選擇，是被迫的**：
按鈕不能巢狀，而翻面按鈕必須在格子裡面。

```html
<div class="slot" data-id="09A" data-done="1" data-face="front">
  <div class="flip">
    <div class="face front" aria-hidden="false">
      <button class="faceopen" data-act="open" data-id="09A">
        未蓋章：分類標籤 / 標題 / 英文標題 / 說明 / 蓋章 →
        已蓋章：分類標籤 / 標題 / 章
      </button>
      <button class="flipbtn" data-act="flip" data-id="09A" aria-label="翻到背面">↻</button>
    </div>
    <div class="face back" aria-hidden="true">
      說明 / 心得 / 照片
      <button class="flipbtn" data-act="flip" data-id="09A" aria-label="翻到正面">↻</button>
    </div>
  </div>
</div>
```

### 3.1 未蓋章不產生背面的 DOM

**未蓋章的格子只渲染正面，連 `.face.back` 都不存在，也沒有翻面按鈕。**

使用者原本想的是兩面永遠都在；改成這樣的理由：沒有東西可以翻到的時候不該有翻面按鈕，
而一個空的背面在 DOM 裡只會被讀螢幕的人聽到、被搜尋功能找到、被下一個人誤以為是 bug。
33 格裡多數時候大半是未蓋章的，少產生一半的節點也不是壞事。

### 3.2 點擊怎麼分派

既有的事件委派是 `e.target.closest("[data-act]")`。翻面按鈕是 `.faceopen` 的**兄弟**
不是子孫，所以：

- 點翻面按鈕 → 最近的 `[data-act]` 是它自己 → `flip`
- 點面上其他地方 → 最近的是 `.faceopen` → `open`

**不需要 `stopPropagation`。** 委派天生就對，這也是為什麼翻面按鈕不能放進 `.faceopen` 裡。

### 3.3 手機：不可以「點整格就翻」

使用者指名的約束。手機一格佔滿寬度，滑動時很容易誤觸。

- 翻面**只能**由那顆按鈕觸發，點擊區限定在按鈕上，最小 44×44px
- 正面整區可點**開蓋章視窗**維持不變 —— 誤觸的後果是「開了一個視窗」，
  按取消就回去，不會改到任何東西；誤觸翻面則會讓人以為內容不見了

## 4. 狀態

`S.flipped[id]` 是 `"front"` / `"back"` / 不存在（用預設）。

預設：**一律正面**。未蓋章只有正面；已蓋章的正面有章（見 §1.1），
所以 `flipped[id] === "back"` 才翻過去。

**只活在 session 裡**，不進資料庫、不進備份檔、不進 localStorage。
翻到進度牆再回來記得住，重新整理就回到預設。它是介面狀態不是護照內容 ——
跟 `intro_seen` 不同的是，那個要跟著帳號走，這個不用。

`ui.js` 加一個純函式當**唯一定義點**：

```js
faceOf(S, a) → "front" | "back"
```

`slotHTML` 與任何之後要知道「這格現在哪一面朝上」的地方都問它，
不准任何一邊自己再判斷一次。這跟 `SLOT_ORDER`、`pagesOf`、`milestoneState`
是同一條原則，理由也一樣：兩個地方各判斷一次，改了其中一邊另一邊會靜靜地說謊。

## 5. 動畫與時序

### 5.1 為什麼不能用 transition

`main.js` 的 `render()` 是 `el.innerHTML = ...` —— **整棵子樹每次都被拆掉重建**。
CSS transition 永遠不會跑，因為要過渡的那個元素沒有活到下一幀。

既有的 `.stamp.land` 與 `.page.turn` 之所以會動，正是因為它們是 keyframe **animation**、
在插入的當下播放。翻面必須用同一個機制。

**不要「改善」成 transition，也不要為了 transition 去改 `render()` 的重繪方式。**
那會把一個穩定的架構換成一個需要 diff 的架構，代價遠大於一個動畫。

### 5.2 ~~先翻面、翻完再落章~~（已被 2026-08-25 的設計改動取代）

**這一節描述的機制已經不需要了，但原文保留在下面。**
章移到正面之後（§1.1），蓋章時章直接落在正面，不需要先翻面，
所以那條 `animation-delay` 的串接與 `animation-fill-mode:backwards` 都被移除。
手動翻面的動畫（`turning-back` / `turning-front`）留著。

保留原文的理由見 §10 裁定 2 的註記。

> 使用者的要求：「蓋章成功後：先翻面，翻完再放章的落下動畫。兩段接在一起，不要同時。」
>
> **用 `animation-delay` 串接，不要用 JS 計時器。** 兩段動畫都在插入時播放，
> 章的那段的 delay 等於翻面的時長。
>
> 使用者原本想的是計時器；改成這樣的理由：計時器會跟下一次 `render()` 競態 ——
> 使用者在動畫還沒跑完時翻頁或蓋下一個章，計時器仍然會觸發，而它要操作的 DOM 已經不在了。
> `animation-delay` 沒有這個問題：元素被移除，動畫跟著消失。
>
> 實作上沿用既有的 `justStamped` 旗標模式，新增一個 `justFlipped`：
> `slotHTML` 讀到旗標就加上動畫 class，並把旗標消耗掉。

`justFlipped` 的機制本身仍然有效，只是不再與蓋章串接。

### 5.3 prefers-reduced-motion

使用者指名這是**無障礙需求不是視覺偏好**，所以要有機器守門，不能只寫在 CSS 裡。

reduce 開啟時**不做 3D 翻轉，直接切換內容**（`animation:none`，最終狀態不變）。

守門用**通用檢查**而不是只釘翻面那一條：`check.sh` 呼叫一小段 node，
把 CSS 裡宣告 `animation` 的選擇器全部抓出來，跟 reduce 區塊關掉的比對，少一個就 FAIL。

- 2026-08-18 那次 `.overprint.land` 漏在 reduce 之外，是人工用 CSSOM 逐條比對才抓到的。
  通用檢查讓那件事不可能再發生。
- `transition` 一起掃，但判準不同：animation 一律要關；transition 只有在動到
  `transform` 或位置類屬性（`top`/`left`/`width`/`height`/`inset`/`margin`）時才要求。
  顏色與透明度的過渡不是前庭刺激來源。

**2026-08-25 對現有 CSS 掃描的結果（翻面尚未實作）**：

```
宣告 animation：.page.turn / .stamp.land / .overprint.land
reduce 關掉的： 同上三個
→ 全部涵蓋，沒有漏的

宣告 transition：.tabs button（背景、顏色）/ .slot（框線色、背景）/ .btn（透明度）
→ 沒有任何一條動到位置或形狀
```

也就是說這條檢查上線時是綠的，它擋的是未來。

## 6. 高度

兩面的內容長度差很多（未蓋章的正面有說明、已蓋章的背面有說明與照片）。要求是翻面時高度不跳、同列三格等高。

**做法：`.flip` 用 `display:grid`，兩面都放在 `grid-area:1/1` 疊起來。
容器的高度自動是兩面的最大值。**

使用者給的兩個選項是「固定高度」或「取兩面最大值」；這是第三個 ——
它就是取最大值，但由排版結構自然產生，不用 JS 量、不用寫死數字，
內容改了也不用回來調。

**2026-08-25 瀏覽器實測**（三格一列，第一格兩面長度不同）：

```
只放正面        容器 88px
只放背面        容器 145px
兩面疊放        容器 145px      ← 等於較高的那面
翻面前後        145 → 145       不跳
同列三格        145 / 145 / 145 等高（grid row stretch）
transform-style 實測為 preserve-3d，與 display:grid 共存
```

`.slot` 既有的 `min-height:270px` 保留當地板（月份頁的格子要留出章的位置，
見該規則的註解）。

### 6.1 背面朝外時不會吃到點擊

**實測**：`backface-visibility:hidden` 同時擋掉指標事件 ——
背面朝上時點中央，命中的是背面的內容，不是被藏起來的正面。
**不需要額外的 `pointer-events:none` 補丁。**

## 7. 無障礙

- 朝外的那一面加 `aria-hidden="true"`，否則讀螢幕的人會聽到兩份內容
- 翻面按鈕有 `aria-label`（「翻到正面」／「翻到背面」），不能只有一個符號
- 翻面按鈕的點擊區至少 44×44px
- reduced-motion 見 §5.3

## 8. 測試

- `faceOf` 的預設與覆寫（未蓋章、已蓋章、手動翻過）
- `slotHTML`：未蓋章只有正面且**沒有** `.face.back`、沒有翻面按鈕
- `slotHTML`：已蓋章兩面都在、預設 `data-face="front"`（章在正面）
- `slotHTML`：已蓋章的正面有章、沒有說明；背面有說明、沒有章
- 翻面按鈕的 `aria-label` 隨當前面向改變
- 朝外那面的 `aria-hidden`
- 既有的 `slotCount`（數 `class="slot"`）在新結構下仍然正確 —— 這條會擋住
  「不小心讓一格變成兩個 `.slot`」
- reduced-motion 的通用檢查（`check.sh`）

**版面相關的（高度不跳、同列等高、44px 點擊區、背面不吃點擊）測試碰不到，
要在瀏覽器實測並附 `window.innerWidth` 自證。**

### 10.1 裁定 2 為什麼保留而不刪掉

章移到正面之後（§1.1），蓋章不再需要先翻面，那條串接整個消失。
但裁定 2 的原文與理由留在表格與 §5.2 裡，使用者 2026-08-25 的原話：

> 記錄的價值在於它當時是對的判斷，不是它永遠有效 ——
> 刪掉會讓下一個人以為我們沒想過那件事。

也就是說：如果之後有人再提「蓋章時做個翻面動畫」，他會看到我們想過、
用過、以及為什麼不用 JS 計時器。刪掉的話那段推理要重來一次。
