# 信件範本

Supabase → **Authentication** → **Emails** → **Templates**，每一種各貼一次。

**這幾個 `.html` 檔裡不准出現註解。** 貼進後台的是整份檔案的內容，HTML 註解在
信件原始碼裡是看得到的 —— 2026-09-01 對外簡介頁就發生過內部註解漏到公開頁面上。
維護者要講的話全部寫在這個 README 裡，那樣它不會跟著信寄出去。

| 後台的名字 | 檔案 | 主旨 |
| --- | --- | --- |
| Reset Password | `reset-password.html` | 重設你的 BT 密碼 |
| Confirm signup | `confirm-signup.html` | 確認你的 BT 帳號 |
| Change Email Address | `change-email.html` | 確認你的新 email |

主旨要另外填在後台的 Subject 那一格，**不在檔案裡**。

## 三條規矩

**連結一律用 `{{ .ConfirmationURL }}`，不准寫死網址。** 那個變數展開出來不只是
一個網址，裡面帶著一次性的 token；寫死的話信裡的連結會指向一個沒有 token 的頁面，
使用者點進去只會看到「這個連結無效或過期了」，而信本身看起來完全正常。
check.sh 有一條在守（每份剛好一次，而且不准有 `href="http`）。

**排版只用最基本的 HTML。** 沒有圖片、沒有表格、沒有外部 CSS、沒有網頁字體。
信件客戶端對 HTML 的支援差異很大，而版型越花俏越容易被判成垃圾信 ——
我們花了一整個階段把 SPF / DKIM / DMARC 弄成三項全 pass，不值得在這裡賠掉。
字體是系統字體堆疊（`PingFang TC` / `Noto Sans TC` / `Microsoft JhengHei`），
不是下載的字體，所以不違反「不用中文網頁字體」那條。

**中文靠 SMTP 那一層的 UTF-8，不是靠檔案裡的 meta。** 信件的字元編碼是
Content-Type 標頭決定的，Supabase 送的是 `charset=UTF-8`。在 body 片段裡塞
`<meta charset>` 沒有作用，別加了以為有保險。改完一定要真的寄一封出來看，
亂碼在後台的預覽裡不一定看得出來。

## 「不要回覆這封信」那一句為什麼獨立成一段，而不是放在頁尾

**這一句是必要資訊，不是禮貌用語。** `noreply@beyondtaiwannpo.com` 沒有 MX 紀錄，
按回覆會被退回，而那個人只會覺得沒有人理他 —— 他不會再想別的辦法聯絡我們。
一個學生放棄的方式通常不是抱怨，是安靜地不再試。

2026-09-02 第一次實測收到的信裡，這一句**沒有出現**。當時它在一個
`border-top` + 小字 + 灰色的頁尾 `<div>` 裡，也就是長得就像簽名檔的那種區塊。
原因沒有查清楚（可能是信件客戶端把尾巴收進「⋯」裡，也可能是貼進後台時沒貼完），
但兩種原因指向同一個修法：**把它變成本文的一部分**，跟其他句子同樣大小、
同樣顏色，沒有分隔線、沒有頁尾容器。這樣不管當初是哪一種原因都不會再發生。

check.sh 現在會檢查三份都有這一句、也都有組織信箱。

> 下次再發生「信裡少了某一段」時，先做這個分辨：在 Gmail 打開那封信 →
> 右上角選單 → **顯示原始郵件**，搜尋那段文字。
> 在原始碼裡 → 是客戶端把它藏起來了（顯示問題）。
> 不在原始碼裡 → 後台的範本內容真的缺了那段（貼上的問題）。
> 這兩件事的修法完全不同，不分辨就會修錯邊。

## 視覺美化排在階段 7（2026-09-02 使用者裁定）

信件現在只有最基本的排版。**刻意不在這個階段美化**：階段 7 要重做首頁與登入頁
的視覺，那時候才有定案的樣子。現在單獨把信件做漂亮，網站改完之後又要跟著改一次，
而且兩邊會有一段時間長得不一樣。

## 沒有放進去的東西，以及為什麼

**沒有 BT logo。** 那需要一個對外可讀的圖片網址，而圖片預設被多數信件客戶端擋掉，
擋掉之後那一塊會變成一個破圖框。用文字署名「— Beyond Taiwan」比較穩。

**沒有「連結按不動的話請複製這一行」加上裸網址。** 使用者要的文案裡沒有這一段，
而且那會讓 token 在信裡出現兩次。**但這件事有一個真的風險**：有些學校或公司的
信件系統會先幫使用者「掃描」信裡的連結，一次性的 token 會在那一刻就被用掉，
使用者真的點的時候反而失效。目前我們的 `/reset/` 頁面碰到這種情況會顯示
「這個連結無效或過期了」加上重新要一封的入口，所以不會卡死，但他會白跑一趟。
真的有人回報「點了說連結無效但我沒點過」的時候，這就是第一個要懷疑的方向。
